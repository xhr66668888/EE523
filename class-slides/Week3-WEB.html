The Layout File: activity_main.xml

  • Defines the UI structure — what appears on screen and where
  • Controls element properties: size, color, text, spacing
  • Enables responsive design across different screen sizes
  • Bridges UI elements to Kotlin code for event handling

LinearLayout

  • Arranges child views in a single direction — either vertical or horizontal
  • our Calculator app: android:orientation="vertical" stacks EditText, Button, and TextView top-to-bottom
  • Key attributes for sizing & spacing:
    • layout_width, layout_height, layout_margin

EditText

  • input field that lets users type text or numbers
  • the Calculator: two EditText fields for number input
    • IDs: @+id/et_a and @+id/et_b
  • Use android:hint to show placeholder text guiding the user

Button

  • tappable UI element that triggers an action when clicked
  • Calculator app uses four buttons: Add, Subtract, Multiply, Divide
    • Example ID: @+id/bt_add
  • Each button's behavior is defined in Kotlin via click listeners

TextView

  • Displays read-only text to the user — labels, results, messages
  • the Calculator: shows the result via @+id/result_tv
  • Style with android:textSize and android:gravity for readability

ImageView

  • Displays images in your app — photos, icons, graphics
  • the Camera app: @+id/selected_image_view shows the captured photo
  • Initially hidden with android:visibility="gone" — becomes visible after capture

Android Permissions

  • Apps must request permission before accessing sensitive device features
  • Camera app requires:
    • android.permission.CAMERA — access the camera hardware
    • Storage permissions — save captured images
  • Permissions are checked & requested at runtime (Android 6.0+ security model)

Beyond the Basics: Exploring Android's Built-in Libraries

Android Jetpack provides ready-made tools so you don't have to reinvent the wheel

Kotlin Jetpack Library

What is Android Jetpack?

  • collection of libraries, tools, and best-practice guidance from Google
  • Simplifies common tasks — less boilerplate, more productivity
  • Handles backward compatibility so your app works on older Android versions

Jetpack at a Glance: Four Pillars

UI Components

    • Build polished, responsive interfaces

Architecture Components

    • Manage data, UI state, and app logic cleanly

Behavior Components

    • Handle notifications, permissions, and camera

Foundation Components

    • Provide backward compatibility and core utilities

UI Components in Android Jetpack

  • View — The basic building block every UI element inherits from
  • RecyclerView — Efficiently displays large scrollable lists and grids
  • ConstraintLayout — Creates complex, flexible layouts with flat view hierarchies
  • Navigation — Manages screen-to-screen navigation and back stack

Architecture Components in Android Jetpack

  • ViewModel — Stores UI data that survives screen rotations
  • LiveData — Observable data holder that auto-updates the UI when data changes
  • Room — A clean abstraction layer over SQLite for local databases

Behavior Components in Android Jetpack

  • Permissions — Simplifies requesting and checking runtime permissions
  • Notifications — Keeps users engaged with timely, relevant alerts
  • CameraX — Modern camera API that works consistently across devices

Foundation Components in Android Jetpack

  • AppCompat — Ensures Material Design features work on older Android versions
  • Android KTX — Kotlin extensions for cleaner, more concise code
  • Multidex — Supports large apps that exceed the 64K method limit

Inside MainActivity.kt: Kotlin in Action

How Kotlin code connects your layout to app behavior

Kotlin Essentials: Key Concepts Overview

  • Class & Inheritance — Your Activity extends AppCompatActivity
  • Lifecycle Methods — onCreate is where your app initializes
  • View Binding — Connect layout elements to code with findViewById
  • lateinit — Defer UI component initialization until onCreate runs
  • View.OnClickListener — Handle button clicks in one central method

Deep Dive: Classes & the Activity Lifecycle

Class & Inheritance in Kotlin

    • MainActivity inherits from AppCompatActivity
    • Gives access to lifecycle methods, UI tools, and backward compatibility

The Activity Lifecycle

    • nCreate is the entry point — called when the Activity is first created
    • This is where you set the layout, bind views, and initialize logic
    • Understanding the lifecycle is essential for managing app state correctly

Deep Dive: View Binding & lateinit

View Binding with findViewById

    • Connects XML layout elements (Button, EditText, TextView) to Kotlin variables
    • Called inside onCreate after setContentView
    • Example: val btn = findViewById<Button>(R.id.bt_add)

Late-Initialized Properties (lateinit)

    • Declares a variable without assigning it immediately
    • Initialized later in onCreate when the layout is ready
    • Avoids null checks — but crashes if accessed before initialization

Deep Dive: Handling Click Events

Setting Up Click Listeners

    • Assign a listener to each button so your app responds to taps
    • Can use lambda syntax or implement the interface directly

View.OnClickListener Interface

    • Implement the interface on your Activity class
    • Override onClick(view: View) to handle all button clicks in one place
    • Use when (view.id) to route each button to its action
